# SpectraLink 部署交接指南（零基础版）

> 本文从零开始，手把手带你完成：下载代码 → 本地跑通 → 部署前端到 Firebase → 确认数据库 → 部署后端。
> 按顺序做即可，每一步都附了命令和预期结果。遇到问题先看最后的「常见问题」。

---

## 第 0 步：先向原负责人要齐这些东西

接手前，请先向原负责人确认以下 4 件事（缺一不可）：

| # | 需要什么 | 用途 |
|---|---------|------|
| 1 | **GitHub 账号加入仓库** `julia-lars/asd_app` | 能 `git clone` 并推送代码 |
| 2 | **Firebase 项目权限**：把你用的 Google 账号加为项目 `asd-app-4e926` 的 Owner 或 Editor | 能执行 `firebase deploy`、查看 Firestore 数据库 |
| 3 | **DeepSeek API Key**（`sk-` 开头的一串字符） | 后端 AI 对话功能要用，密钥不会随仓库分发 |
| 4 | **服务账号 JSON 文件**（`service-account.json`，或在 Firebase 控制台自己生成，见 5.4） | 后端读写 Firestore 数据库用 |

> ⚠️ 原负责人给你这些之前，你先把下面第 1 步的软件装好。

## 第 1 步：安装三个软件

### 1.1 安装 Node.js

1. 打开浏览器，访问 <https://nodejs.org/>
2. 下载 **LTS 版本**（左边绿色按钮，版本号 20 或 22 开头均可）
3. 双击安装包，一路点「继续/Next」完成安装

装好后验证（打开「终端」应用，粘贴下面命令，回车）：

```bash
node -v
```

看到类似 `v22.x.x` 就成功了。

### 1.2 安装 Git

macOS 上打开终端运行：

```bash
git --version
```

- 如果显示版本号（如 `git version 2.39.x`）→ 已安装，跳过
- 如果提示安装 → 按提示安装即可（或去 <https://git-scm.com/> 下载）
- Windows 用户请到 <https://git-scm.com/download/win> 下载安装

### 1.3 安装 Firebase CLI

终端里运行（需要 Node.js 已装好）：

```bash
npm install -g firebase-tools
```

验证：

```bash
firebase --version
```

显示版本号即成功。

## 第 2 步：下载代码（git clone）

1. 确认你的 GitHub 账号已被原负责人加入仓库（第 0 步第 1 项）
2. 打开终端，进入你想放代码的目录，运行：

```bash
git clone git@github.com:julia-lars/asd_app.git
```

> 如果提示 `Permission denied (publickey)`，说明 SSH 没配。**零基础推荐改用 HTTPS 方式**：
>
> ```bash
> git clone https://github.com/julia-lars/asd_app.git
> ```
>
> 运行后会让你输入 GitHub 用户名和密码（密码处粘贴 GitHub 的 Personal Access Token，或直接用浏览器登录授权）。

3. 进入代码目录：

```bash
cd asd_app
```

现在目录里有 `frontend/`（前端，React 网站）和 `server/`（后端，Node 接口服务）两个主要文件夹。

---

## 第 3 步：本地把项目跑起来（强烈建议先做）

先在本地跑通，再谈部署，出问题好排查。

### 3.1 跑前端

```bash
cd frontend
npm install        # 安装依赖，首次约需 1-3 分钟
npm run dev        # 启动开发服务器
```

看到 `Local: http://localhost:5173/` 后，用浏览器打开 <http://localhost:5173>，能看到网站界面即成功。按 `Ctrl + C` 可停止。

> 本地开发时前端默认不连后端。如果要本地调试 AI 对话，需要先启动后端（见 3.2），然后在 `frontend/` 下新建一个 `.env` 文件，内容为：
>
> ```
> VITE_API_BASE_URL=http://localhost:3001
> ```
>
> 新建后重启 `npm run dev`。

### 3.2 跑后端

```bash
cd ../server
npm install
```

然后需要两个本地配置文件（**这两个文件都不会随仓库分发**，从第 0 步要来的材料里取）：

**① 创建 `server/.env`**（把引号里的值换成真实值）：

```bash
cp .env.example .env
```

用文本编辑器打开 `.env`，填上 DeepSeek Key（`server/.env.example` 是模板，照它填）：

```
DEEPSEEK_API_KEY="sk-你从原负责人那里拿到的真实key"
PORT=3001
DEEPSEEK_MODEL="deepseek-chat"
```

**② 放置 `server/service-account.json`**：

把原负责人给你的 `service-account.json` 文件，直接复制到 `server/` 文件夹里（文件名必须叫 `service-account.json`）。没有这个文件也不要紧——自己生成的方法见第 5.4 步。

**启动：**

```bash
npm start
```

看到 `[server] listening on http://localhost:3001` 和 `[firebase] Admin SDK 已初始化` 即成功。

浏览器访问 <http://localhost:3001/api/health> 之类接口能返回内容，说明后端活了（具体接口以代码为准）。

## 第 4 步：部署前端到 Firebase Hosting

### 4.1 登录 Firebase

```bash
firebase login
```

浏览器会弹出 Google 登录页：

1. 登录你的 Google 账号（**必须是被加了 Firebase 项目权限的那个账号**，第 0 步第 2 项）
2. 授权同意
3. 终端显示 `✔ Success! Logged in as xxx@gmail.com` 即成功

### 4.2 把本地代码关联到 Firebase 项目

```bash
cd frontend
firebase use asd-app-4e926
```

> 若提示项目不存在，说明你的 Google 账号没有项目权限，回到第 0 步找原负责人加权限。

### 4.3 构建生产版本

```bash
npm run build
```

这一步会先自动生成知识图谱数据（`build:kg`），再打包出 `dist/` 文件夹。看到 `✓ built in xx.xxs` 即成功。

### 4.4 上传部署

```bash
firebase deploy --only hosting
```

完成后终端会显示网站地址：`https://asd-app-4e926.web.app`。浏览器打开，能看到和本地一样的网站即部署成功 ✅

## 第 5 步：确认 Firebase 数据库（Firestore）

本项目的数据库是 Firestore。**正常情况下数据库已经建好并在使用中，你只需确认**：

1. 打开 Firebase 控制台 <https://console.firebase.google.com/>（用同一个 Google 账号登录）
2. 进入项目 `asd-app-4e926`
3. 左侧菜单点 **构建 → Firestore Database**，应该能看到 `users`、`posts` 等数据集合

### 5.1 如果看不到数据库（说明还没创建过）

在 Firestore Database 页面点「创建数据库」：

- 位置：选离用户近的区域（**选定后永久不能更改**，建议与原负责人确认当前生产数据所在区域，务必一致）
- 规则模式：选「生产模式」后按 5.3 调整规则

### 5.2 检查安全规则（重要）

⚠️ 前端「社交」页面的帖子是**浏览器直接**读写 Firestore 的 `posts` 集合（见 `frontend/src/pages/Social/Social.jsx`），所以规则必须允许 Web 端读写，否则社交功能会报 `permission denied`。

在 Firestore 控制台的「规则」标签页查看现有规则：

- **如果网站当前社交功能正常**：说明现有规则没问题，**保持原样，不要改**
- 如果规则是锁定状态（`allow read, write: if false;`）而社交功能不可用，可参考设为（测试环境用，上线后建议按需收紧）：

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if true;
    }
  }
}
```

### 5.3 后端如何连数据库

后端（server）通过 **Admin SDK + 服务账号** 读写 Firestore，不受安全规则限制（Admin SDK 绕过规则）。所以只要 `service-account.json` 配置正确，后端就能用数据库。

### 5.4 自己生成服务账号 JSON（替代第 0 步第 4 项）

如果你拿不到现成文件，可以自己生成：

1. Firebase 控制台 → 项目 `asd-app-4e926` → 右上角齿轮「项目设置」→「服务账号」标签
2. 点「生成新的私钥」→ 下载 JSON 文件
3. 把这个文件重命名为 `service-account.json`，放到 `server/` 文件夹里

> ⚠️ 这个文件是服务器私钥，**永远不要提交到 GitHub、不要发给任何人**。仓库的 `.gitignore` 已配置忽略它。

## 第 6 步：部署后端到 Render

后端目前部署在 Render（免费计划），服务名 `asd-app-api`，前端通过 `frontend/.env.production` 里的 `https://asd-app-api.onrender.com` 访问它。

### 6.1 方式 A（推荐）：请原负责人把你加进 Render 团队

1. 让原负责人在 Render 控制台 → 服务 `asd-app-api` → Settings 中，把你的邮箱加为成员
2. 你注册 Render 账号（<https://render.com/>，可用 GitHub 登录）并接受邀请
3. 这样部署服务、环境变量（DeepSeek Key 等）都不用重新配置，**直接跳到第 8 步验证**即可

### 6.2 方式 B：自己从零部署（如果方式 A 不可行）

1. 注册 Render 账号（用 GitHub 登录）
2. Render 控制台 → New → **Blueprint**
3. 连接你的 GitHub 账号，选择 `julia-lars/asd_app` 仓库（需要你对该仓库有权限）
4. Render 会自动识别仓库里的 `server/render.yaml`，创建名为 `asd-app-api` 的服务
5. 创建完成后，进入服务 → **Environment**，手动补填环境变量：

| 变量名 | 值 |
|-------|-----|
| `DEEPSEEK_API_KEY` | 第 0 步要来的真实 Key |
| `DEEPSEEK_MODEL` | `deepseek-chat` |
| `MCP_TRANSPORT` | `stdio` |
| `FIREBASE_SERVICE_ACCOUNT_PATH` | `service-account.json` |

6. 上传 `service-account.json`：服务 → Environment 页面下方有 **Secret Files** 区域，新建一个名为 `service-account.json` 的文件，内容粘贴你本地这个文件的全文。**这个文件绝对不能提交进 GitHub**，所以必须走 Secret Files。
   - （或者替代方案：把服务账号 JSON 全文存为环境变量 `GOOGLE_APPLICATION_CREDENTIALS_JSON`，代码会自动识别，见 `server/firebaseInit.js`）
7. 等待部署完成，日志里出现 `listening on http://localhost:3001` 即成功

> Render 免费计划：服务 15 分钟无人访问会休眠，之后第一次访问要等 1 分钟左右才响应，这是正常的，不是挂了。
>
> Stripe 支付相关变量（`STRIPE_SECRET_KEY` 等）不配置不影响注册登录和 AI 对话，只有付费订阅功能不可用。

## 第 8 步：日常更新流程（以后改代码怎么发布）

以后每次改了代码，发布分两部分：

### 前端（改了 `frontend/` 里的东西）

```bash
cd frontend
git pull                 # 先拉取最新代码
npm run build            # 重新构建
firebase deploy --only hosting   # 上传
```

### 后端（改了 `server/` 里的东西）

```bash
git add <改动的文件>
git commit -m "描述你改了什么"
git push
```

推送后 Render 会自动重新部署（服务 Settings → Deploy 里确认 Auto-Deploy 是开启的），等 1-3 分钟即可生效。

## 第 9 步：安全红线（务必遵守）

1. **`service-account.json`、`.env`（含 DeepSeek Key）绝不能提交到 GitHub**。它们已被 `.gitignore` 忽略；提交前永远用 `git status` 检查一遍，只 `git add` 你真正改的文件，不要无脑 `git add .`
2. 根目录下的 `asd-app-4e926-firebase-adminsdk-*.json` 是服务账号私钥，同样禁止提交（已在 `.gitignore` 中）
3. 不要提交 `.mov` 录屏等大文件
4. 不确定的时候，先 `git status` 看要提交什么，再动手

## 常见问题（FAQ）

| 现象 | 原因与解决 |
|------|-----------|
| `firebase login` 后 `firebase use asd-app-4e926` 提示无权限 | 登录的 Google 账号不是项目成员，找原负责人加为 Editor |
| `firebase deploy` 报 `Authentication Error` | 凭证过期，重新 `firebase login` |
| 本地 `npm run dev` 打开网页正常，但 AI 对话报错 | 后端没启动，或 `frontend/.env` 没配 `VITE_API_BASE_URL=http://localhost:3001` |
| 社交页报 `permission denied` | Firestore 安全规则不允许前端读写 `posts`，见第 5.2 步 |
| 后端日志报 `[firebase] Admin SDK` 初始化失败 | `server/service-account.json` 缺失或路径不对，见第 5.4 步 |
| 网站第一次打开很慢（1 分钟左右） | Render 免费计划休眠冷启动，正常现象 |
| 国内网络访问 `*.firebaseapp.com` / Firestore 不稳定 | 需要网络代理；后端已内置 Firestore 超时熔断，对话不会卡死 |
| `npm run build` 报错 | 确认在 `frontend/` 目录下执行，且 `npm install` 成功过；Node 版本需 20.19+ 或 22.12+ |
